# 海报阅读清单前向试做

直接打开 [index.html](index.html) 即可操作。海报与标题是这个页面的虚构内容。清单和撤销记录在当前页面会话内有效。连续撤销按移除顺序的逆序执行，每张海报回到原始排序位置。

## 技能依据与页面决定

- 《视觉语言》中的稳定阅读层、短促命中和几何收束，决定了纸色、粗墨轮廓和硬阴影。海报与墨线使用原创 CSS 形状，克制方案适合连续浏览。
- 《动作规格》中的原生激活和批次所有权，决定了同步更新列表、消息与按钮可用状态。当前批次最多两段 WAAPI 动画，可整体取消。减少动画偏好变化、页面进入隐藏状态和后续操作都会清理当前批次。
- 《页面与场景》将恢复关联到原锚点和低能量回落。我为移除选择了清单内状态条上的票据作为主体，防止项目重排时的动作与新位置按钮争夺注意力。票据以托板为接触边，约 58 ms 压扁并发出两道短墨线，215 ms 回稳。恢复时原位置的缩略图向右入框，约 96 ms 到达边缘并回稳，整段 185 ms。标题、说明和控件保留其实际位置。
- 清单的 LIFO 撤销、在条目消失时优先聚焦后项、再到前项或撤销，以及撤销用尽时聚焦最后恢复的条目，都是这次页面特定的交互决定。

## 实际运行

在无头 Chromium 159.0.8154.6 执行 [verify.mjs](verify.mjs)，[报告](evidence/report.json) 记录七组通过和零页面错误。真实输入路径覆盖指针按住和移出取消、8 ms 内的快速移除和双击撤销、Tab／Enter／Space、按住 Enter 时的重复输入、清空后连续恢复、390 CSS px／DPR 2 的模拟触摸和减少动画初值。中途偏好切换测试在暂停活跃批次后进行，确认效果立即清除，状态保留。关闭减少动画偏好后，由下一次操作启动新批次。

另以 WAAPI 的 `currentTime` 独立采样，逐帧检查 [按住](evidence/remove-000ms-held.png)、[58 ms 移除命中](evidence/remove-058ms.png)、[107 ms 移除余势](evidence/remove-107ms.png)、[220 ms 移除终态](evidence/remove-220ms.png)、[0 ms 恢复起始](evidence/restore-000ms.png)、[90 ms 恢复落点](evidence/restore-090ms.png) 和 [190 ms 恢复终态](evidence/restore-190ms.png)。在 [1200 CSS px／DPR 1](evidence/desktop.png) 和 [390 CSS px／DPR 2](evidence/mobile-390-dpr2.png) 查看了布局。物理触屏、屏幕阅读器播报、其他浏览器的手感尚未实测。

## 指导缺口

- 技能说明了撤销的方向、力度和批次的取消，但结构变化时要如何安排真实列表与装饰层，需要从通用规则推断。一个删除将触发列表重排的例子，可以展示如何把命中转移到可信的局部状态标记，以及何时适合用明确隔离的退场影像。
- 技能将状态、焦点和输入放在实现首位，具体的历史语义和焦点移交交由宿主决定。可在连续撤销的验收例里覆盖最后一项消失、恢复顺序，以及撤销按钮禁用后焦点去向。
- 验收页提示给 CSS／WAAPI 独立时钟，但给的可执行取帧方式用于上游 SakugaFX。自有 WAAPI 场景可补充如何分别取定点帧和验证正常速度下的真实输入。
