# 验收动作与证据

## 定时取帧

从动作规格选静止、预备、首个命中、余势、稳定五类时刻。需要时补图查看方向反转、中断、连续触发或出场。记录实际时刻、DPR、裁切范围、输入序列和随机种子，固定种子用于比较，多种种子用于查极端遮挡。画面稳定后应保持真实状态与可读轮廓。

上游 [look.mjs](../assets/upstream/look.mjs) 只推进 `SakugaFX` 的时钟。Node 22+ 和 Chromium，先启动静态服务器，例如在 skill 目录运行下面这组命令中的第一条，在另一个终端运行第二条。

```sh
python -m http.server 8000 --bind 127.0.0.1
node assets/upstream/look.mjs http://127.0.0.1:8000/assets/upstream/starter.html --select like-button --act "0.06:document.querySelector('like-button').shadowRoot.querySelector('button').click()" --times 0,0.067,0.15,0.3,0.55,0.85 --out like-frames.png
```

若 Chromium 未被脚本发现，设置环境变量 `CHROME` 为可执行文件路径。原工具不固定随机性，分段按 60 Hz 四舍五入，外部 CSS/WAAPI、浏览器事件时钟和 toggle 图片解码需要独立控制；脚本点击主要用于采样。新场景在 [Web 示例](../assets/web/index.html) 独立提供暂停、步进与读数，和原工具的时钟互相独立。

如果项目用 WAAPI 或 CSS 动画，在触发后捕获本次动作拥有的 `Animation` 对象，暂停并等待 `ready`，按观察点设置每个对象的 `currentTime`。同批次有不同延时或结束边界时记录它们与场景时间的关系。恢复正常交互前刷新测试页或取消该批动画。逐帧图只验证画面，提交时点和取消路径再用自然时钟检查。

## 正常速度交互

使用目标浏览器的鼠标、键盘、触屏操作或协议事件。查看手感和过程中的视觉干涉，浏览器自动化可读 DOM 与帧计数协助判定。

| 验收对象 | 操作 | 可观察通过条件 |
| --- | --- | --- |
| 命中 | 按住、松开、移出取消、键盘提交、快速重复 | 按压形变随持有，取消无成功反馈，成功状态即时可读，中心文字清晰，同批只落一个主击 |
| 速度对象 | 慢拖、快拖、反向、停住后释放、失焦/取消、键盘与点选 | 形变和尾迹对应向量与速度，收手回稳，取消恢复承诺位置，同一目标可用键盘或点选达到 |
| 场景揭示 | 同样的起点切同一章，在两预设下重复；再快速改目标、反向切换 | 状态、入口与读序一致，能指出持续、位移、轮廓或效果组合的实质差异，过期内容和粒子退出 |
| 减少动画 | 加载前开启，动作中切换，恢复后重试 | DOM、焦点和状态可用，主体归位，效果层清屏，恢复后仅响应新动作 |
| 边界 | 宽屏和 390px，方向变化，DPR 1/2，滚动容器/退出重进，高频触发 | 效果范围受控，不拦点击，确认状态可读，画布对齐，作用域的计时器、粒子和侦听释放 |
| 随机性和性能 | 同种子重拍，换种子检查最坏轨迹；若声称性能，测目标设备 | 首者复现姿态和绘制次序，后者满足预算。性能记录浏览器、硬件、DPR、操作频率、时段、样本与测量口径 |

验证依赖真实控制流。协议触摸/窄视口验证报告应注明模拟条件。移植后原生表单还须检查 FormData、禁用和 reset；屏幕阅读器输出与物理触屏/低端设备行为按目标产品另测。小型手工检查可记录「输入 → 真实状态 → 主体持续 → 画布/字层清除 → 回到静止」。

## 转交验证

用新会话或独立代理，仅提供 skill、一个未演示过的目标任务和必要对象。让其实现并运行一次，不给预期方案或原作者说明。检查实际产物的语义状态、运动因果、分层、取消、偏好与证据；只针对暴露的问题改规则，并重测相关场景。
