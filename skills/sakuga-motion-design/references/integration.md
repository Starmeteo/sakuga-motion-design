# Web 接入与技术适配

## 使用现成组件

1. 从 [固定源码](sources.md) 获取一个 `<name>/<name>.js` 以及其 `README.md`，复制许可。将脚本按普通脚本加载一次。已有上游控件时查 `window.SakugaFX` 的版本和真实加载顺序，先到的核心生效。若项目以 ESM 打包，保留注册副作用，在客户端入口按执行顺序加载；Web Component 的注册与初次属性/属性值写入要协调。SSR 保留普通的语义外壳，客户端环境可用后再注册。
2. 把组件接到项目已有表单、状态管理和业务回调。使用组件真实的属性/事件契约，布尔属性尤其核对 attribute 存在与 property 值的差异。按钮动作成功再调用 `done()`，Progress 的动画完成事件只有在视觉上达到末端才出现，业务完成沿用真实任务结果。Tabs 的内容面板由宿主管理。
3. 先调 CSS 自定义属性，再按需适配 Canvas 和资源。上游用全局核心；任意修改 `P` 会影响同一实例上的其他控件，未必重绘已烘焙的颜色。需要独立主题、容器裁切、软卸载或运行中偏好响应时，可用渲染适配层或独立派生实现。修改共享核心时从根 `core.js` 编辑，在上游树运行 `node tools/build.mjs`，然后用 `--check` 检查生成副本，并单独比对 skill 内副本。
4. 在真实页面验证焦点、禁用、表单提交/重置、重复操作、减少动画和控件拆装。按所选组件执行 [专用检查](motion-recipes.md) 与 [验收](verification.md)。

## 在场景中复用原理

可参考 [原版 Starter](../assets/upstream/starter.html) 与 [核心](../assets/upstream/core.js) 的弹簧和效果签名。两文件保持原版；它们共享全局 RAF、样式和前景画布。原版减少动画阻止新效果入队，已有粒子、弹簧和部分定时器仍可能运行。原版的 `later()` 无直接取消值，组件断开只移除帧回调，不能充当场景销毁合约。可在项目中注入带作用域的时钟和随机源，按场景释放资源。多个脚本如需共存，避免给新系统写入旧核心的全局名称。

| 环境 | 迁移的单位 | 需重验的边界 |
| --- | --- | --- |
| HTML/CSS + Canvas 2D | 原生 DOM、场景容器、独立绘制批次、CSS/Canvas token | stacking context、滚动坐标、DPR 和 resize、透明绘制、媒体查询偏好 |
| React/Vue/Svelte | 框架管理状态和可读 DOM，refs 持有命中面，挂载时建渲染器，卸载时销毁 | SSR、重复挂载、事件穿过 shadow boundary、热更新和异步导入；高频每帧形变使用渲染层更新 |
| SVG/WAAPI/CSS | 用实际对象轮廓和关键姿态得到同步的命中、方向和回稳 | SVG viewBox/变换原点、clipPath、运行中取消与减少动画。若没有 Canvas 可用，先实现主体和少量线条 |
| 原生/Flutter/其他渲染器 | 同一语义状态机、时间单位、资源与帧索引。用平台语义树、动画驱动和 painter | 触屏、系统减动效、逻辑尺与物理像素、帧序列解码、滚动位置、前后台与资源释放，本 skill 的 Web 验证不代表平台验证 |

## 打开随附示例

在 skill 根目录启动 `python -m http.server 8000 --bind 127.0.0.1`。打开 [新场景](http://127.0.0.1:8000/assets/web/) 或 [原版 Starter](http://127.0.0.1:8000/assets/upstream/starter.html)。页面使用相对资源路径，适用于静态托管，ES module 页面通过 HTTP 运行。预览旧核心时保持原许可。
